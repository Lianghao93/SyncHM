# SyncHM — 鸿蒙原生去中心化文件同步

## 一句话介绍

SyncHM 是一款基于 Syncthing 引擎的鸿蒙（HarmonyOS）原生文件同步应用。没有中心服务器，文件在你的设备之间点对点直接同步——数据永远掌握在你自己手里。

## 它解决什么问题

把文件从这台电脑传到那台电脑、在多台设备之间保持文件夹实时一致，通常要依赖网盘：上传慢、有容量限制、隐私存疑。SyncHM 用去中心化的方式解决这些问题：

- **点对点直连**：同一局域网内设备直接通过 TCP/QUIC 传输，速度只受网络带宽限制
- **没有中心服务器**：文件不经过任何第三方云端，不存在"上传到别人服务器"这回事
- **全程加密**：所有传输基于 TLS 1.3，设备之间通过设备 ID（加密证书指纹）互相认证
- **跨平台互通**：与官方 Syncthing（Windows / macOS / Linux / Android）完全兼容，添加对方设备 ID 即可组网

## 核心特性

### 原生性能
同步引擎采用 Go 语言编译的 Syncthing 核心原生库（.so），而非网页套壳或远程服务，CPU 密集型的哈希、压缩、增量索引全部在本机原生执行。

### WebUI 管理界面
内置完整 Syncthing 管理界面（应用内 Web 组件打开，也可用浏览器访问 `127.0.0.1:8384`）：
- 添加/管理同步文件夹与远程设备
- 实时查看连接状态、传输速率、同步进度
- 完整的版本控制与忽略规则配置

### 智能网络穿透
- 自动 NAT 穿透（UPnP/端口映射），外网也能直连
- 局域网本地发现 + 全球发现服务
- 中继 relay 自动接入，极端网络环境下也能保持连接

### 持续后台同步
文件变更事件驱动，增量索引，只传输差异部分；支持断点续传与冲突文件自动保留。

## 技术架构

```
┌─────────────────────────────────────────┐
│  ArkTS 应用外壳（UI / 状态页 / WebUI 容器）  │
├─────────────────────────────────────────┤
│  NAPI 桥接层（C++）                        │
├─────────────────────────────────────────┤
│  Syncthing 引擎（Go → c-shared 原生库）     │
│  · BEP 同步协议（TCP/QUIC，端口 22000）      │
│  · REST API + WebUI（127.0.0.1:8384）     │
│  · LevelDB 增量索引数据库                   │
└─────────────────────────────────────────┘
```

针对鸿蒙的 musl libc 环境完成了 Go 运行时级适配（线程指针两级间接 TLS、事件/config 服务循环、引擎日志桥接 hilog），是Go 生态应用在 HarmonyOS 上完整落地的参考实现。

## 适用人群

- 拥有多台设备（Windows / macOS / Linux / Android / 鸿蒙 PC），希望在它们之间**自动、私密、无容量限制**地同步文件
- 不信任公有云盘，或受限于内网/跨境网络环境
- 需要在局域网内高速搬运大文件（照片库、工程目录、模型文件……）

## 隐私承诺

- 不收集任何用户数据，无账号体系
- 文件只存在于你自己的设备之间
- 传输加密 + 设备认证，未配对设备无法建立连接
- 全部源码基于开源组件构建（Syncthing MPL-2.0）
